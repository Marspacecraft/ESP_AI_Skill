# 代码编写规范（v1.3）

> **状态：定稿 v1.3（2026-10-30）**
>
> v1.3 加了一节 **§10「注释」**：注释用中文、哪些东西必须有注释、函数注释块的四项固定内容（入参 / 返回 / 线程与中断 / 注意事项），以及三条禁令。前九节逐字未变。
>
> v1.2 加了一节 **§9「内存与内联」**：内联的规模上限、多套实现时选内存小的那套、栈 > 静态 > 动态的优先序、以及"内存申请只能走 `fw_` 层，C++ 必须重载 `new`/`delete`"。
>
> 适用范围：本仓库与产品仓库里的**全部 C11 源码**（`common/` `api/` `framework/` `platform/` `apps/` `tests/`）。
> 第三方代码与生成代码不适用。

---

## 1. 一条总则

**每个符号都要能回答两个问题：它由哪一层实现、它是函数还是数据。**

- 由哪一层实现 → 决定**层前缀**。
- 是函数还是数据 → 决定**形态**（函数用后缀规则、类型以 `_t` / `_e` 结尾、宏全大写）。

## 2. 层前缀：谁实现写谁的

前缀**表示实现它的那一层，不表示谁在调用**。

| 层 | tag | 前缀 | 例 |
|---|---|---|---|
| 应用层（系统 App / 业务 App） | 1 / 2 | `app_` | `app_render_page`、`app_open_book` |
| 框架层 | 3 | `fw_` | `fw_app_start`、`fw_delay_block` |
| 平台层 | 4 | `pf_` | `pf_mem_alloc` |
| 接口层 | 5 | `api_` | `api_version`（版本与编译期开关；能力接口见 §2.1，用能力名做前缀） |
| 公共基础库 | — | `cm_` | `cm_tls_set`、`CM_ERR_TIMEOUT` |

- 前缀之后接**这个符号自己的名字**，不重复层名：`fw_app_start`，不写 `fw_framework_app_start`。
- `static` 函数同样带层前缀——它只在文件内可见，但仍然属于某一层。
- **后果要认**：应用层最常调的那批函数（延时、分配、日志）实现在框架层，所以它们带 `fw_` 前缀，App 代码里写 `fw_delay_block(100)`。这是刻意的——前缀告诉你"出问题该找谁改"，而不是"你属于谁"。
- 应用层自己写的函数才带 `app_`。
- 宏与枚举值全大写、同样带层前缀：`PF_MUTEX_FOREVER`、`CM_ERR_TIMEOUT`。

### 2.1 例外：能力接口用能力名做前缀

`api/af_api/<能力>.h` 里给 App 用的那批函数**不按层前缀命名**，用人读的能力名：

| 能力 | 前缀 | 例 |
|---|---|---|
| 显示 | `disp_` | `disp_commit`、`disp_cancel` |
| 输入 | `input_` | `input_obtain` |
| 音频 | `audio_` | `audio_play` |
| 存储 | `stor_` | `stor_open`、`stor_read` |
| 网络 | `net_` | `net_connect` |
| 电源 | `power_` | `power_sleep` |
| 资源 | `res_` | `res_acquire`、`res_lock` |
| 能力查询 | `cap_` | `cap_available` |

理由：能力接口的**实现方不唯一**——`stor_read` 由存储服务 App 实现，`res_acquire` 由框架实现。按"谁实现写谁的"会把同一个头切成 `app_` 与 `fw_` 两种前缀，而调用方根本不关心是谁实现；能力名唯一（一个能力只有一个所有者），且直接回答"这是哪个能力的接口"。

约束：

- 能力前缀只出现在 `api/af_api/<能力>.h` 与解析到它们的转发层实现里；转发层导出的符号就是这批能力函数本身，不再叠加 `fw_`。
- 能力名**不得与层名重合**：`app_ / fw_ / pf_ / api_ / cm_` 保留给层前缀。
- 新增一个能力前缀 = 新增一处公共契约，必须同时登记进能力目录（`docs/generated/catalog.md`）。

## 3. 变量

**snake_case：全小写，多词用下划线连接。** 本项目不使用驼峰。

```c
int      page_index;
size_t   pixel_count;
bool     is_ready;          /* 布尔用 is_ / has_ / can_ 开头 */
app_id_t owner_app;
```

- 布尔量一律 `is_` / `has_` / `can_` 开头，名字本身就能读出真假。
- 指针不加 `p` 前缀（`buf`，不是 `pBuf`）；不加匈牙利式类型前缀（`nPage` 错）。
- 全局变量如果必须存在（`common/` 本身禁止需要初始化的全局状态），同样 snake_case。

## 4. 函数

**`<层>_<名>[_<后缀>]`**，全小写。

```c
fw_delay_block(100);        /* 层前缀 + 名 + 阻塞后缀 */
fw_app_state_of(3);         /* 多词用下划线，无后缀 */
pf_mem_alloc(size);
cm_tls_get(slot);
```

### 后缀：非必要不加

后缀只在**从名字看不出来、但调用方必须知道**时使用。目前只有两个：

| 后缀 | 何时加 | 例 |
|---|---|---|
| `_block` | 这个调用**会阻塞**（含伪阻塞：可能永远不返回） | `fw_delay_block()` |
| `_accurate` | **精准**延时（不是"大致等一会儿"） | `pf_delay_accurate()` |

规则：

- 后缀放在最后，不能插在名字中间（`fw_block_delay` 错）。
- 拿不准就不加——**多一个后缀是噪声，少一个后缀是隐患**，只在"调用方会因此写错代码"时才加。
- 返回值、错误码不进函数名（`fw_get_errno_ok` 错，用返回值）。

## 5. 类型

**结构体、联合体、整数句柄以 `_t` 结尾；枚举以 `_e` 结尾；指针类型以 `_p` 结尾；类以 `_c` 结尾（本仓库不用）。** 全部小写 snake_case。

```c
typedef struct { ... } app_desc_t;      /* 结构体 */
typedef enum   { ... } pf_state_e;      /* 枚举 */
typedef uint16_t      svc_id_t;         /* 标量别名（整数句柄也用它） */
typedef struct res_s *res_p;            /* 不透明句柄：本质是指针，按指针规则 */
```

- **指针类型加 `_p`，指针变量不加前缀。** 两者不冲突：`res_p handle;` 里类型带 `_p`、变量 `handle` 不带 `p` 前缀（§3）。类型带 `_p` 的理由：C 里 `res_p` 与 `res_t` 在声明处长得一样，`res_p h` 让人一眼知道 `h` 是指针。
- 句柄按表示的形态分：用整数表示（如 id）用 `_t`；指向不完整结构体的指针用 `_p`。
- **类型前缀不强制。** 类型名表达"它是什么"，不是"谁实现的"——`app_desc_t`（App 的描述体）里的前缀指的是**被描述的对象**，不是写它的那一层。带不带看会不会混淆：契约类的类型带上更清楚（`pf_state_e`），本身就是专名的可以不带（`res_p`）。注意**"不强制"不等于"可以随便加"**——`plat_` 不是任何一层的前缀，属于待迁移的旧名，新代码里不能用。
- 枚举**值**全大写、带层前缀：`PF_STATE_RUNNING`、`CM_ERR_TIMEOUT`。
- 不要在类型名里重复 `struct` / `enum` 关键字（写 `struct app_desc_t` 错，应为 `app_desc_t`）。

## 6. 成员变量：只针对类，不针对结构体

**结构体与联合体的成员不加任何前缀。**

```c
typedef struct {
    app_id_t      id;
    const char   *name;
    cm_err_t    (*init)(app_ctx_t *ctx);
    void        (*exit)(app_ctx_t *ctx);
    void        (*task)(app_ctx_t *ctx);
    uint32_t      flags;
} app_desc_t;

app_desc_t d = { .id = 3, .name = "reader", .flags = 0 };
```

- `_` 前缀是**类成员**的约定。本仓库是纯 C11、没有类，所以**这条在当前代码里不生效**。
- 将来若产品仓库引入 C++ 类，类成员才以 `_` 开头；那时同样禁止 `__x` 与 `_X`（大写）——C 与 C++ 都把这两种保留给实现（C11 §7.1.3）。
- 结构体成员不加前缀的理由：C 里读成员永远带 `.` 或 `->`，本身就区分得清楚；再加 `_` 只是噪声。

## 7. 文件

- 文件名与目录名全小写 snake_case：`app_manifest.c`、`cm_tls.h`。
- 一个模块一对 `.h` / `.c`，名字相同；`.h` 只放声明、类型、宏。
- 头文件守卫：`<目录>_<文件>_H`，如 `API_AF_API_APP_H`。
- `#include` 顺序：自己的头 → `api/af_api/` → `api/fp_api/` → `common/` → 标准库。每组之间空一行。
- 只 include 用得到的头；`framework/` 与 `platform/` 的 include 受 `policy.txt` 的读权约束。

## 8. 排版

- 缩进 **4 个空格**，不用 tab。
- 大括号**不换行**（K&R）：

```c
for (;;) {
    do_work();
    fw_delay_block(100);
}
```

- 单行不超过 **100 列**。
- `if` / `for` / `while` **必须带大括号**，哪怕只有一行——伪阻塞的"不返回"最怕少一对括号。
- 指针 `*` 贴变量名：`const char *name`。
- 一元运算符贴操作数；二元运算符两侧空格；`,` 后空格。
- 不留行尾空白，文件以单个换行结尾。

## 9. 内存与内联

这一节比前八节"软"：**没有门禁脚本判定，靠评审**。所以每一条都要求把理由写出来——否则事后分不清是有意选的，还是压根没想过。

### 9.1 内联：默认不写

**默认不写 `inline`。** 只有函数体**不超过 5 行**的实现才允许内联，且要在旁边写一句为什么内联它。

```c
/* 只在头文件里包一层取值，函数体 2 行 —— 允许 */
static inline uint16_t cap_mask_of(cap_id_t cap)
{
    return (uint16_t)(1u << (uint8_t)cap);
}
```

- 头文件里的 `static inline` **只允许是这个规模**。大函数标 `inline` 不会更快，只会让每个编译单元多一份代码副本。
- `.c` 里的 `static inline` 更没必要——同一文件内的静态函数，编译器本来就会自己决定要不要内联。
- **不写 `#define` 宏来代替函数**：宏没有类型检查、不能下断点，而且伪阻塞的"不返回"在宏里更容易写错。

### 9.2 有多套实现时，选内存占用小的那套

**凡是有两种以上可行实现，优先选静态内存占用小的那一套**（RAM 与代码段都算），除非小的那套有明确代价：速度差一个数量级、可读性崩到没人敢改、需要关中断或占着锁做长事。

- 选大的那套时，**理由写进提交清单**（"用了 XX 换 YY 的原因是 Z"）。
- 这条只裁决"实现方式"，不裁决"要不要申请内存"——后者看 9.3。

### 9.3 内存来源：栈 > 静态 > 动态

1. **能用栈就用栈。** 局部变量、小的临时缓冲一律放栈上。
2. **其次静态。** 但静态是常驻的：它一直占着 RAM、初始化要自己保证、多任务共享时并发由你负责。**"省了一次分配"不能成为静态的理由。**
3. **大块内存优先动态申请。** 大缓冲放到栈上会直接爆栈（任务是 4096 字节栈，见 `docs/app-model.md` §9.4），放到静态区则常驻不还——**该动态的时候就动态**。

**凡是要用静态内存或动态内存的，都必须评审。** 提交清单里单列一行，写清五件事：

| 项 | 写什么 |
|---|---|
| 申请什么 | 对象/缓冲的名字与类型 |
| 多大 | 字节数（静态写常量大小，动态写最坏情况） |
| 谁释放 | 哪段代码负责（静态的是"谁在什么时候重置"） |
| 什么时候释放 | 正常路径之外还要写：取消、`FAILED`、重启时怎么回收 |
| 申请失败怎么办 | 返回什么错误码、上一状态怎么退回 |

**没有这一行的清单，评审不通过。** 这是流程要求，不是风格偏好——伪阻塞下"清理只能放 `exit()`"，忘了写这五行，泄漏就会留在框架里没人认领。

### 9.4 内存只能从 `fw_` 层拿

**任何代码申请内存，都必须经过框架层的唯一入口**（`fw_alloc` / `fw_free`，声明在 `api/af_api/res.h` 一族里，见 `docs/architecture.md` §5）。理由：框架要在 `res_track` 里登记托管资源、要在 `exit()` 里回收、要在配额超限时拒绝。

- **禁止**直接调用 `malloc` / `calloc` / `realloc` / `free` / `strdup` / `aligned_alloc` / `posix_memalign`。
- **禁止**用 STL 的默认分配器（`std::vector`、`std::string`、`std::make_unique` 等）——它们是换了个名字的 `new`。
- **C++ 必须重载 `operator new` / `operator new[]` / `operator delete` / `operator delete[]`**，全部转到 `fw_alloc` / `fw_free`。重载放在应用层的公共头里，一处定义，所有 `.cpp` 都用它。没重载就等于绕过了配额与回收。
- 新代码出现 `malloc(` 之类，评审直接打回，不问理由。
- **例外只有一处**：`platform/` 里实现 `pf_ops_t` 内存项的那一层（`pf_mem_alloc` 的实现）——它本身就是"内存从哪来"的背面，是被评审过的既定设计。**"我在平台层"不构成例外**，平台层的其他代码同样只能走 `fw_` 层。

### 9.5 这些都要人拍板

"要不要用静态内存""要不要动态申请""这个 `inline` 算不算小"——**都由人决定，AI 不得自己拍板**。两条路径：

- 清单里列出来、等人批（正常路径）；
- 或者标成"待定"，先做不依赖它的部分。

## 10. 注释

### 10.1 注释用中文

注释写**简体中文**；标识符、类型名、宏名、错误码保持英文原样，不要翻译。

```c
/* 好：配额不足时返回 NULL，调用方用 fw_errno() 取 CM_ERR_NOMEM */
/* 坏：quota 不足时 return NULL，调用方用 fw_errno() 取 内存不足 */
```

句子要写完整。**禁止半截话**——"这里要锁"读的人还是不知道该锁什么。

### 10.2 哪些必须有注释

**必须**：

- 公共头文件里声明的**每个函数**（§10.3 的四项）。
- **全局变量**与文件级 `static` 变量（用途 + 谁写它 + 并发约定）。
- 结构体里**不自明的字段**（单位、取值范围、谁能改）。
- 任何"看着像普通写法、其实有约束"的地方：必须持锁、必须最后调用、必须在中断外、失败后要重试。

**不必**：局部变量（名字够清楚时）；`i++` 这种自明的赋值。

### 10.3 函数注释块：四项固定内容

```c
/*
 * fw_alloc —— 从配额里分配一块内存，并登记进资源表。
 *
 * 入参：size   要多少字节；0 视为参数错误
 *       owner  归属的 App id；必须是已注册的 id
 * 返回：成功返回指针；配额不足/参数错返回 NULL，错误码见 fw_errno()
 * 线程：任务上下文可并发调用（内部持锁）；**不可在中断里调用**
 * 注意：必须在 App 退出前 fw_free；忘掉的会在 exit() 阶段被回收并记一条日志
 */
void *fw_alloc(size_t size, app_id_t owner);
```

四项**缺一不可**，某项没有就写"无"——空着和不适用是两回事，读的人分不清。

| 项 | 写什么 |
|---|---|
| **入参** | 逐个写名字 + 含义 + 边界（0、NULL、超长、负数） |
| **返回** | 成功是什么；失败有哪几种；**失败时输出参数是什么状态**（未改？已清零？） |
| **线程** | 任务上下文能否并发；要不要调用方自己加锁；**中断里能不能调**（不能就直接写"不可在中断中调用"） |
| **注意** | 谁负责释放/关闭；会不会阻塞（含伪阻塞：可能永远不返回）；调用顺序；时长上限；平台差异 |

**中断可用性是必答项。** 写"不可在中断中调用"比什么都不写有用得多——不写，别人会试。

### 10.4 变量注释

```c
static cm_mutex_t g_pool_lock;   /* 保护 g_pool：只在持锁时读写，初始化在 fw_init() */
static uint8_t    g_pool[4096];  /* 常驻池，不释放；用了多少见 g_pool_used */
```

- 全局/静态变量：**用途 + 谁写它 + 并发约定** 三样齐全。
- 宏与常量：为什么是这个值（`/* 4096 = 任务栈的 1/4，再大会挤掉 IDLE */`）。

### 10.5 三条禁令

1. **不写"是什么"能看出来的**：`i++; /* i 加一 */` 只是噪声，还占一列。
2. **不留过期注释**：改代码必须同步改注释。**旧注释比没注释更坏**——它会让下一个人按错误的前提改代码。
3. **不用注释代替命名**：一个名字需要三段注释才能解释，说明名字起错了，去改名字。

### 10.6 门禁不查注释

`tools/` 里没有任何脚本判定注释质量，**唯一保证是评审**：评审时先看"这个函数有没有四项注释块"，没有就退回，不往下看实现。
