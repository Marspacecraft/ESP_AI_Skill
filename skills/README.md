# skills · 按角色拆的四份作业指导

`AGENTS.md` 是**所有人**的入口（规矩、四行交付、停手条件）。这里四份是**按身份**展开的
细则：同一个仓库里，四个人关心的事几乎不重叠，混在一份里会让每个人读到 80% 与自己无关的内容。

## 路由

| 你要做 | 身份 | 读 |
|---|---|---|
| 新建/修改一个 App | 业务 App（tag 2） | [`role-app/`](role-app/SKILL.md) |
| 改框架机制（伪阻塞、退出、注册表、配额、事件、心跳） | 框架层（tag 3） | [`role-framework/`](role-framework/SKILL.md) |
| 把一块新板接进来、实现 `pf_ops_t`、烧录真机 | 平台层（tag 4） | [`role-platform/`](role-platform/SKILL.md) |
| 定义公共契约：`api/`、`common/`、`platform/port/`、文档 | 接口层（tag 5） | [`role-api/`](role-api/SKILL.md) |

**身份不明就先问。** tag 是分层，不是人：一个人可以同时持多个 tag，
写权是各行的并集，判定只认 `python3 tools/check_workspace_policy.py --as <tag> <路径>`。

## 每份 skill 都有这几节

1. **动手前先确认你写得了** —— 两行判定命令 + 真实输出（含退出码 1 = 停）。
2. **你能写什么 / 碰不到什么** —— 只列这一层，不重复 `policy.txt` 全文。
3. **这一层独有的坑** —— 全部来自真事故（真机日志、TSan 报告、门禁红证），不是"最佳实践"。
4. **标准流程** —— 每步带一条可验证的成功判据。
5. **交付前自查** —— 只列这一层必须跑的命令。
6. **该读什么** —— 3–5 行指针，不复制内容。

## 两条写作规矩

**不复制 `AGENTS.md`。** 规则只有一处：交清单、四行交付、停手条件、`SKIP`≠通过。
这里只写"这一层怎么判断"，需要全局规矩时给链接。复制一份的代价是两份会漂移，
而漂移的规则比没有规则更糟。

**每个坑都要能指到一个证据。** 写"小心栈溢出"没有用；写"1024 字节栈打一行日志就
`Stack protection fault`，所以下限是 3072"才有用。证据可以是：真机日志、测试红证、
门禁报错原文、`实施步骤.md` 的 D 号。

## 加一份新 skill

目前四份对应 tag 2/3/4/5。tag 1（系统 App，`apps/system/`）还没有产物，所以没有 skill——
等产品仓库真的开始写系统 App 时再加，不要先写一份没人能验证的。

新增时：`skills/role-<名字>/SKILL.md`，frontmatter 只写 `name` 与 `description`
（`description` 是唯一触发机制，要写"什么时候用"，不是"这是什么"）。

## 谁写这里

`skills/` 已划进 `nobody`（2026-11-03，人授权）：与 `tools/`、`build.sh`、`AGENTS.md`
同一类——它们是**给 AI 看的说明书**，让 AI 改说明书，它会把约束改写成自己做得到的样子。
所以 AI 只能报告"这份 skill 与现实不符"，改由人动手。
